## 五、1.2.112 回归的完整复盘（最重要的一节——防止重蹈）

**现象**：用户 2026-11-25 全天连不上车机。

**根因（时序竞态）**：1.2.109 的 join 预检判定「链路已死」用的信号是 `iap2Ready && sessionActive`，但这两个信号在 0x5703 凭据到达时刻**必然还是 false**：

```
0x5703 到达 → onWifiCredentials 触发 join 预检   ← 此刻判定
iap2Ready     ← 要等 Iap2SenderSession.run() 返回后才置（BtSession.kt:52）
sessionActive ← 要等拿到 AirPlay 端点后才置（SessionController.kt:6922）
→ 判定时刻两者必为 false → 100% 误判 → 全天 52 次误杀
```

**修复**：`BtSessionGate.controlChannelEstablished`（claimControl 置 true / releaseControl 置 false），`controlLinkAlive` 改三条件任一即活。1.2.109 的原始意图（死链不陪跑 join）保留：链路真终结（releaseControl）后判死。

**教训（已入长期记忆，通用）**：跨模块状态预检必须核对**判定信号在目标时序点是否已置位**。单测全绿挡不住这类回归——原测试也用了同样的错误信号。任何新增的「前置条件检查」，先画一遍信号置位时序图再写判定。
